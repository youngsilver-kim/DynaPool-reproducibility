# GitHub and release checklist

## Commit to the repository

- Training and evaluation code: `dynapool/`, `train.py`, `download_data.py`
- Analysis and audit code: `analyze.py`, `measure_efficiency.py`,
  `audit_experiment.py`, `scripts/plot_figure3.py`
- Tests and environment: `tests/`, `requirements.txt`
- Reproduction notebook: `colab/DynaPool_Reviewer_Revision.ipynb`
- Documentation: `README.md`, `REVIEWER_CHECKLIST.md`, `PROVENANCE.md`
- Small audited result subset: `paper_results/`
- `LICENSE` and `.gitignore`

## Attach to the GitHub Release

- `reviewer_revision_v1_evidence_A100_fixed.zip`
- Optional SHA-256 checksum text file for the ZIP

Use a release tag such as `jics-reviewer-revision-v1`. Explain the retained
training snapshot and its `git_commit: null` metadata exactly as documented in
`PROVENANCE.md`; do not rewrite experiment metadata retroactively.

## Do not publish

- Tiny-ImageNet image files or archives
- `model_final.pt`, `checkpoint_last.pt`, or other checkpoints
- Google Drive paths, credentials, tokens, cookies, or Colab secrets
- T4 archives mixed with the final A100 evidence
- Duplicate manuscript drafts, reviewer PDFs, or personal working files
- `__pycache__/`, `.pytest_cache/`, notebook checkpoints, and generated figures
  that can be regenerated by the supplied scripts

## Final commands

```bash
pytest -q
python scripts/plot_figure3.py
python audit_experiment.py \
  --experiment-dir /path/to/reviewer_revision_v1 \
  --seeds 13 42 2026 \
  --require-efficiency

git add .
git commit -m "Release reproducible DynaPool experiments and Figure 3"
git branch -M main
git push -u origin main
git tag -a jics-reviewer-revision-v1 -m "JICS reviewer revision evidence"
git push origin jics-reviewer-revision-v1
```

Create the release only after the commit and tag are visible on GitHub. Upload
the full evidence ZIP as a release asset rather than committing it to Git.
